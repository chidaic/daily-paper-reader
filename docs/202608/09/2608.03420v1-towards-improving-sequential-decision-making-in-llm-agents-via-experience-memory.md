## 摘要
大型语言模型在单次推理任务上已有显著提升，但它们在序列决策中的表现尚未被充分理解。我们在完全可观察的双人零和游戏中对此进行研究，该类游戏提供了真实结果评估：结果由规则决定，且个体移动的最优性可计算或近似，无需依赖裁判模型。在不同模型层级中，LLM在简单游戏（如井字棋或四子棋）中表现欠佳，并输给MCTS对手。保持游戏树不变但改写其表面形式的混淆处理几乎不改变性能，表明这一差距不能完全由记忆策略的回溯来解释。鉴于这一性能差距，我们引入了一个为序列设置设计的、带有经验记忆的智能体框架，以解决序列决策中常见的挑战，如信用分配。我们表明，游戏后反思和规则提取在不动模型权重的情况下，能在井字棋上带来可测量的改进。

## Abstract
Large language models have improved substantially on single-shot reasoning tasks, but their performance in sequential decision-making is less well understood. We study this on fully-observable two-player zero-sum games, which provide ground-truth evaluation: outcomes are determined by the rules, and optimality of individual moves can be computed or approximated, without relying on a judge model. Across model tiers, LLMs play suboptimally in simple games such as tic-tac-toe or Connect Four, and lose to MCTS opponents. Obfuscations that preserve the game tree but rewrite its surface form leave performance largely unchanged, indicating the gap is not fully explained by recall of memorized strategies. Motivated by this performance gap, we introduce an agentic framework enhanced with an experience memory designed for the sequential setting and addressing common challenges of sequential decision-making such as credit assignment. We show that post-game reflection and rule extraction yield measurable improvements on tic-tac-toe without modifying the model weights.

## 1. 论文的核心问题与整体含义

- **研究动机**：大型语言模型（LLM）在单步推理任务上表现卓越，但在序列决策（sequential decision-making）场景中能力显著不足。当环境逐步演化、存在对抗对手、奖励延迟到达时，前沿模型也会在人类容易掌握的简单游戏中犯错。
- **核心问题**：LLM 在完全可观察的双人零和博弈（井字棋、Nim、四子棋）中能否进行可靠的序列决策？其表现不佳的原因是否可归因于对已记忆策略的机械回忆，而非真正的状态推理？
- **研究意义**：
  - 通过带 ground-truth 的游戏环境，对 LLM 序列决策能力进行无偏评估；
  - 引入基于经验记忆的智能体框架 REAPER，在不修改模型权重的前提下提升序列决策能力；
  - 为将 LLM 部署为可靠自主智能体提供了一条轻量、可行的改进路径。

## 2. 方法论

### 2.1 核心思想

- 保留 LLM 作为主体推理器，不进行权重更新。
- 通过外部经验记忆，在决策时向 LLM 提供来自过去对局的结构化上下文。
- 核心挑战是信用分配：终局延迟奖励无法区分局中每一步的好坏，REAPER 通过“逐走子反思 + 规则提炼”解决该问题。

### 2.2 关键技术细节

- **PlyBench 评估平台**：
  - 基于 OpenSpiel 游戏引擎；
  - 提供 Interface Adapter 和 LLM Adapter，将游戏状态与动作转换为统一表示和自然语言文本；
  - 支持任意玩家（LLM、MCTS、Optimal、Random）、游戏和混淆变体。

- **REAPER 架构**（Reflective Experiential Agent with Periodic Extraction of Rules）：
  - 保留 planner-executor 循环与案例记忆（case memory）；
  - **Game Buffer**：缓存单局内的所有走子，直到终局；
  - **Self-reflector**：每局结束后，对完整轨迹逐走子生成结构化反思，从“局部质量”和“结果贡献”两个维度打分，避免将终局胜负粗粒度地平均分配给每一手；
  - **Rule extractor**：每固定局数后，将积累的反思案例蒸馏为约 20 条自然语言战略规则，且要求规则为位置无关的通用原则，可迁移到未见状态；
  - **State descriptor**（可选）：将原始观测转换为自然语言状态描述用于检索，但实验发现其无效，作为辅助组件单独评估。

- **检索与决策循环**：
  - 使用句子编码器（SimCSE-BERT）将状态描述嵌入，按余弦相似度检索 top-8 案例；
  - 采用分层抽样（stratified retrieval），正负案例各占约一半，避免检索邻域被单一结果主导；
  - Planner 与 executor 通过结构化 JSON 通信；planner 输出“计划”或“最终答案”，最多 3 次迭代；输出非法或解析失败记为失败。

## 3. 实验设计

- **场景（游戏）**：
  - 井字棋（tic-tac-toe）：小博弈树，最优结果为平局，测试避免失败的能力；
  - Nim：初始堆 {1,3,5,7}，先手必败，测试基于 Nim-sum 的符号策略应用能力；
  - 四子棋（Connect Four）：较大博弈树，先手胜，需要长时域规划与多重威胁创建。

- **对手**：
  - Random（均匀随机）；
  - MCTS（井字棋/Nim 模拟预算 n=1000，四子棋 n=5000）；
  - Optimal（Minimax 最优策略，最优平局时均匀随机打破平局）。

- **模型分组**：
  - Efficient：GPT-5 nano、Gemini 3.1 Flash Lite、GPT-OSS 120B；
  - Intermediate：GPT-5 mini、Gemini 3 Flash、Qwen 3.5 122B；
  - Frontier：GPT-5.4、Gemini 3.1 Pro、GLM-5.2。

- **基准与对比方法**：
  - 单次调用 LLM 参考（无记忆）；
  - Original：Memento 的直接移植（每走子生成一次完整 planner-executor 任务）；
  - Baseline：工程化改进版（结构输出、记忆去重、分层检索）；
  - REAPER 变体：反射（Refl.）、反射+规则（Refl.+Rules）、再加状态描述符（Refl.+Desc.+Rules）。

- **评估指标**：
  - 井字棋/Nim：每步最优率（per-move optimality），排除所有动作均最优的状态；
  - 四子棋：胜率、平均步数；
  - REAPER 实验：平局率（主指标）、每步输出 token 数。

## 5. 实验数量与充分性

### 5.1 实验数量

- 标准评估：每模型-对手组合 100 局（四子棋 10 局），前后半场互换先后手；
- 混淆评估：每种混淆形式 100 局，共 5 种井字棋形式（TTT、Hid、M.Sq、M.Sq+5、Story）和 4 种 Nim 形式（Nim、Hid、Inv、Story），部分结果见附录；
- REAPER 实验：每配置 10 次独立运行；每次运行先 50 局空记忆评估，再经历 5 轮“20 局学习 + 50 局评估”，评估时冻结记忆；
- 消融实验：反射 vs 反射+规则、状态描述符开关、Original/Baseline/REAPER 对比；

- **充分性**：主结果均有 95% 置信区间（Wilson、Student t），关键差异使用单侧 Welch t 检验，统计处理较规范；REAPER 与 Baseline 共享同一架构，消融可隔离贡献。
- **局限性**：
  - 四子棋仅 10 局，样本量偏小，置信区间宽；
  - REAPER 仅在井字棋 + GPT-5 nano + Optimal 对手上验证，泛化证据不足；
  - 未对 Frontier 模型测试 REAPER；
  - 状态描述符消融结果不利，说明检索机制仍有缺陷。

## 6. 主要结论与发现

- **存在普遍的顺序决策能力缺口**：
  - Efficient/Intermediate 模型在井字棋上每 100 步犯 4–12 次错误；Nim 上较小模型仍犯错；
  - Frontier 模型在四子棋中几乎每局输给 MCTS，平均仅 10.3 步即落败，失败发生在开局阶段。

- **表面混淆不改变性能**：
  - 保持博弈树不变的混淆（Magic Square、Story 等）对最优率影响不大，且无跨模型一致退化模式；
  - 模型常能从规则中识别出底层游戏，但即使识别率下降（如 M.Sq+5 上 Gemini 3.1 FL 仅 25.6%），最优率仍接近最优——说明差距主要来自决策时推理，而非记忆召回。

- **REAPER 有效**：
  - Original（Memento 直接移植）完全不可用，平局率始终为 0（大量非法动作/解析失败）；
  - Baseline 达到 0.818 平局率；
  - REAPER（反射+规则）达到 0.868，比 Baseline 高 5 个百分点（p=0.018），且每步输出 token 数低于 Baseline 与单次调用参考；
  - 规则提取比单独反射带来显著提升（平局率 0.826→0.868，最优率 0.959→0.970）。

## 7. 优点

- **评估无偏**：使用完全可观察零和博弈，结果由规则决定，无需 LLM 裁判，避免主观偏差；
- **记忆 vs 推理分离**：设计了多种语义等价的规则混淆，为区分“记忆召回”与“状态推理”提供了有效实验范式；
- **不修改权重**：REAPER 通过外部记忆提升能力，避免微调成本与灾难性遗忘风险；框架组件可独立开关，支持模块化消融；
- **统计严谨**：报告置信区间、显著性检验，并区分“局部最优”与“结果贡献”的信用分配，方法设计有洞察力；
- **成本透明**：给出 token 消耗分析，显示性能提升并非来自更长推理链，而是更有效的决策上下文。

## 8. 不足与局限

- **实验覆盖有限**：REAPER 仅在井字棋（一个模型、一个对手）上评估，未展示在 Nim、四子棋、更大博弈树或部分可观察环境中的效果；
- **四子棋实验样本量过小**（每模型仅 10 局），结论稳健性不足；
- **检索机制依赖已见状态**：无法对未见状态直接泛化，规则提取缓解有限；状态描述符试图解决但失败，说明嵌入空间中的状态匹配仍不稳健；
- **记忆污染风险**：模型一旦识别出游戏（如 Magic Square 本身是知名谜题），仍可能使用记忆中的策略，无法彻底排除记忆影响；
- **模型识别与策略来源无法完全解耦**：推理轨迹中命名底层游戏的比例只能作为下界，无法确定模型是否真正“理解”规则；
- **算力信息缺失**：远程 API 推理导致无法评估能耗、硬件成本等资源指标，只能依赖 token 数作为代理；
- **部署问题未讨论**：经验记忆随对局增长而增大，检索与存储的长期扩展性、规则更新的稳定性等尚未分析。
