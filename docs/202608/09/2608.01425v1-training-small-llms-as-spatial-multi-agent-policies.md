## 摘要
使用多智能体强化学习训练基于LLM的多智能体系统正迅速获得关注，而一条并行的工作线认为此类系统应以其行为而非仅凭奖励来评判。我们在空间合作游戏中同时采纳这两条思路，其中使用低级动作提示的小型冻结LLM会彻底失败，获得零奖励。在选项/半MDP框架——以及由于选项执行在智能体间是异步的，其在宏动作Dec-POMDP中的多智能体扩展——的指导下，我们为每个游戏配备一个符号化的“选项”库：由符号规划器执行的带类型、状态可行、短视界行为。每个库由前沿编码模型根据游戏源代码起草；随后通过廉价的随机策略预热回放机械地合成过滤每个菜单的可行性守卫——只有当守卫能解释重复的执行失败且不隐藏任何已记录的成功时才会被采用——因此没有守卫是手动编写、选择或通过奖励调优的。每个智能体的LLM充当其策略，作用于选项，使用按智能体变体的多智能体GRPO（PA-MAGRPO）训练的私有按智能体LoRA适配器；这将冻结的基础模型从零奖励提升到在三个游戏和四个小型骨干上的胜任表现。行为审计随后揭示奖励与合作脱钩：上升的奖励曲线可能仅意味着一个智能体学会了独自完成整个任务，而同伴闲置——只有当任务使合作成为必要时，合作才会出现。因此，仅凭奖励不是合作的可靠读数；行为评估必须与其并置。

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

## 论文总结

### 1. 核心问题与整体含义（研究动机和背景）

本论文聚焦于**如何将小型 LLM（2–4B 参数）训练为空间合作多智能体系统中的智能体策略**，并在此基础上审视“奖励是否足以衡量合作水平”这一关键问题。

- **研究背景**：训练 LLM 智能体的多智能体强化学习（MARL）正在兴起；同时学术界日益认识到，仅以奖励评价多智能体系统是不够的，还需对智能体行为进行直接审计。
- **三大训练障碍**：
  1. **接地缺口（grounding gap）**：小型冻结 LLM 无法将高层目标可靠地转化为环境接受的底层动作，产生“空间幻觉”并坍缩在单一“安全”动作上，导致奖励恒为零。
  2. **视野问题（horizon problem）**：回合长达数百个底层步，稀疏团队奖励下几乎无可用的逐决策信用信号。
  3. **特化问题（specialization problem）**：合作常需智能体扮演不同角色，但共享权重训练会平均化冲突的角色梯度，使智能体趋于同质化。
- **核心论断**：论文通过行为审计进一步揭示了**奖励与合作脱钩**——奖励上升可能仅仅意味着某个智能体学会了包办而同伴闲置；合作只在任务结构强制要求时才会涌现。因此，行为评估必须与奖励指标并行使用。

### 2. 方法论：核心思想、关键技术细节、算法流程

论文提出一套由**符号选项库 + 机械守卫合成 + per-agent LoRA + PA-MAGRPO** 构成的完整训练食谱。

**（1）符号选项库与菜单接口**

- 将 LLM 的决策空间从底层动作（上/下/左/右/交互）提升为**符号化的短视界选项**（如 `move_to(x,y)`、`pick_up(onion)`、`clean(dirt)`），选项由符号规划器展开执行。
- 形式化映射：确定性可行性检查实现 **initiation set**；符号执行器实现 **intra-option policy**；完成/失败/超时实现 **termination condition**。
- 形式上，单智能体面临半 MDP，多智能体团队则建模为**宏动作 Dec-POMDP**。
- 每个决策点，LLM 看到的是**经状态过滤后的字母化可行菜单**，只需选择“做什么”（what），不需要决定“怎么做”（how）。

**（2）选项库构建流程（仅一次前沿模型步骤，其余全机械）**

- **Stage 1（唯一模型步）**：Claude Opus 4.8 读取游戏源代码，起草带四部分契约的选项库：实例化、执行器、终止条件、**效果谓词**（delta 形式）。
- **Stage 2 预热回放**：用均匀随机菜单策略跑大量回放（约 55 万决策，单 CPU 核约 70 秒），记录每个选项执行的有效/无效标签（由效果谓词判定，与奖励无关）。
- **Stage 3 守卫合成**：分显式通道（执行器带类型失败原因出现≥5 次即成为守卫）与推断通道（覆盖≥5 个失败且**覆盖 0 个成功**的 1–2 字面量合取即被采纳）。纯化要求是验收证明：任何掩盖成功的合取都被拒绝，从而防止策略性知识进入守卫。
- **Stage 4 菜单组装**：逐目标实例化选项、应用守卫过滤、每决策用种子 RNG 打乱字母顺序（防止字母位置泄漏选项身份）。
- **外层契约修复循环**：若契约（Stage 1 产物）有缺陷，机械层检测到（异常模式/证明失败），前沿模型修复 schema，重新运行 Stage 2–3。文中详述了三个缺陷族：绝对形式效果谓词导致的空转假成功、共享状态归属错误、最近目标实例化导��的死选项。

**（3）Per-agent LoRA + PA-MAGRPO**

- 每个智能体拥有**私有的 LoRA 适配器**（共享一个冻结的基础模型），策略为 πⁱ_θi = f ∘ θi。私有参数使角色分歧可以累积而非被梯度平均掉。
- **PA-MAGRPO** 为每个智能体独立计算 PPO-clipped surrogate loss（只用自己的决策计算重要性比值），但所有智能体共享同一团队奖励带来的群组相对优势（cohort-normalized advantage）。
- 更新仅在选项边界发生；回合折扣设为 1（episodic undiscounted return），无需半 MDP 折扣机制。
- 完整训练轮流程：收集 K 条联合回放 → 计算团队回报 → 组内归一化得共享优势 → 每个智能体在其私有决策上做 E 个 PPO epoch（带 KL 惩罚）→ 只更新各自 LoRA。

### 3. 实验设计：场景、基准、对比方法

- **三个合作空间游戏**：
  - **Melting Pot Cleanup**（clean_up 基质，7 智能体，150 步）：河流需清理污物，果园在污物阈值以下才长苹果——经典序贯社会困境。
  - **Overcooked-AI**（2 智能体，400 步）：两个分离厨房布局。**Asymmetric Advantages（AA）**：每侧可独立完成汤，合作可选；**Forced Coordination（FC）**：两侧互补，必须交接才能完成——构成“可选 vs 强制合作”的组内对照。
  - **Commons Harvest**（commons_harvest_no_thinning，7 智能体，400 步）：6 个共享补丁上的苹果需可持续采摘——公共资源困境。
- **四个小型骨干**：Qwen3-4B-Instruct-2507、Qwen3.5-2B、gemma-4-E4B-it、gemma-4-E2B-it（每个 5 个独立训练种子）。
- **六个消融单元**（在固定 Qwen3-4B 上进行，单训练种子）：
  - **Full method（ours）**：选项菜单 + per-agent LoRA + MAGRPO
  - **Ablation A（native + MAGRPO）**：去掉抽象，直接在原始动作上训练
  - **Ablation B（选项菜单 + 共享 LoRA）**：保留菜单但替换为单一共享适配器
  - **Ablation C（冻结 + native）**：无训练无抽象
  - **冻结 + 选项菜单**（无训练基线）
  - **Ablation D（compound-JSON + per-agent LoRA）**：保留宏动作语义但移除可行性过滤和离散菜单
- **评估协议**：训练种子控制选项库采样、LoRA 初始化、环境初始状态、小批量顺序；评估用与训练不相交的 20 个固定种子回合；报告均值±标准差；显著性用 Mann–Whitney U 检验与 bootstrap 置信区间。

- **跨骨干研究**：4 个骨干模型 × 5 个训练种子 = 20 条端到端独立训练轨迹，每个训练种子还控制了选项库采样。
- **消融套件**：在固定 Qwen3-4B 上完成 6 个设计单元的对比（单训练种子 × 20 评估回合）。

### 6. 主要结论与发现

- **方法有效**：冻结基础模型在所有游戏上全部为零奖励，而完整方法在四个骨干上均获得正奖励：Cleanup 60.25–105.69、Overcooked AA 6.21–7.31、Commons Harvest 85.41–115.52。
- **选项菜单不可省**：去掉抽象直接在原始动作上训练（Ablation A），所有游戏一律坍缩为零。
- **per-agent LoRA 不可省**：共享 LoRA（Ablation B）在 Cleanup 上几乎无法稳定表达角色分工（0.10±0.45），Overcooked 仅达完整方法的约 1/3。
- **可行性过滤有价值**：无过滤的 compound-JSON（Ablation D）在 Overcooked 上无法逃离零，在 Cleanup 上方差巨大。
- **奖励与合作脱钩（双向）**：
  - **高估**：Overcooked AA 高奖励来自“一人干活、一人闲置”（agent 1 有 72% 时间在 wait），零交接；FC 对照中 solo 测试为 0，证明合作确实出现。
  - **低估**：Commons Harvest 奖励几乎持平（76.73→98.29），但 patch 存活从“全部灭绝于 ~200 步”变为“~2.5/6 存活至 400 步”——可持续性显著改善。
  - **合作跟随任务激励结构，而非奖励曲线**：Cleanup 涌现真实的清理者/食者分工，Overcooked AA 无合作，FC 必须合作，Commons Harvest 出现节制行为。

### 7. 优点：方法与实验设计亮点

- **守卫合成全机械化**：可行性守卫从随机预热的执行日志中统计合成（覆盖失败、零成功即采纳），不含任何人工设计或奖励调优，避免了人为注入策略性偏见。
- **“一次性前沿模型”设计**：前沿模型只在构建期作为“代码作者”使用一次，训练、评估、动作选择均不再查询——降低了运行时 API 成本与不确定性。
- **防御性工程细节充分**：效果谓词改用 delta 形式避免空转假成功；共享状态效果绑定私有变迁防止错误归属；逐目标实例化防止可达目标被屏蔽；菜单字母随机打乱防止字母位置泄漏身份。
- **训练种子的语义明确**：每个种子控制界面、初始化、回放随机性和优化顺序，是完整的端到端独立运行，反映整个管线的方差而非仅评估噪声。
- **行为与奖励并重的评估框架**：通过 solo 测试、宏分布直方图、热力图、patch 存活等多层次行为指标，直接支撑“奖励与合作脱钩”的核心论断。

### 8. 不足与局限

- **规模与泛化受限**：结果仅覆盖 ≤4B 的小型 LLM 和三个空间游戏；更大规模模型或非空间任务（比如纯文本合作任务）的迁移性未验证。
- **选项空间缺乏选择原则**：选项库是逐游戏手工委托前沿模型构建的，论文承认没有系统性的原则来选择好的选项空间。
- **行为结论的统计保证有限**：“角色专门化”的空间划分仅在一个种子/一个检查点上做了热力图验证；消融套件为单训练种子，其 bootstrap 区间仅反映评估侧方差而非全管线方差。
- **对比基线不足**：没有与前沿模型直接 prompting 或更大型模型的性能对比（作者指出设置差异导致无法直接数值比较）。
- **外部效度问题**：Forced Coordination 对照依赖于“非 solo 可解”的布局假设；解耦发现是行为证据而非一般理论。
- **格式稳定性瑕疵**：训练后的模型中仍有少量决策违反输出格式（文中记录 8 次中 1 次解析失败），提示接口鲁棒性有待提升。
