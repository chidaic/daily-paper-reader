## 摘要
当前视频世界模型在多智能体环境中面临困难，因为它们将世界状态与依赖于视角的视觉潜在变量纠缠在一起，导致计算冗余、视角不一致以及可扩展性差。我们提出MAS（具有权威共享状态的多智能体世界模型）来解决这一局限。受多智能体游戏架构的启发，MAS将世界动态与视角渲染分离。一个学习得到的逻辑引擎从联合动作中推进全局、权威的类型化状态，无需任何手写转移函数，并作为唯一的循环记忆和同步参考。基于这一共享状态，一个学习得到的渲染引擎按需为任意请求的视角生成独立且一致的视图。这种显式的解耦使MAS在匹配的多智能体Snake基准测试中，相较于先进的多视角基线方法，实现了更高的状态准确性和更低的跨视角不一致性。它推进了包含1,024个并发智能体的预测世界，持续10,000个循环步骤。我们的结果表明，显式的权威状态建模为可扩展且一致的多智能体世界模拟提供了实用基础。

## Abstract
Current video world models struggle in multiplayer environments because they entangle world state with view-dependent visual latents, leading to redundant compute, view inconsistencies, and poor scalability. We propose MAS (Multiplayer world models with Authoritative Shared State) to resolve this limitation. Inspired by multiplayer game architectures, MAS disentangles world dynamics and view rendering. A learned Logic Engine advances a global, authoritative typed state from joint actions without any hand-written transition function, acting as the sole recurrent memory and synchronization reference. From this shared state, a learned Rendering Engine generates independent and consistent views for any requested camera on demand. This explicit disentangling allows MAS to achieve superior state accuracy and lower cross-view inconsistency compared to state-of-the-art multi-view baselines on a matched multiplayer Snake benchmark. It advances predicted worlds with 1,024 concurrent players for 10,000 recurrent steps. Our results show that explicit, authoritative state modeling provides a practical foundation for scalable and consistent multi-agent world simulation.

## 1. 论文的核心问题与整体含义（研究动机和背景）

现有视频世界模型（如 GameNGen、Oasis、DIAMOND 等）通常将“世界状态”与“视角相关的视觉潜变量”耦合在一起，用像素或视觉潜变量同时充当循环记忆和下一帧预测的输入。这种设计在单人游戏环境中可以工作，但扩展到多人游戏时会产生严重问题：

- **计算冗余**：每个玩家视角都各自维护一条独立的循环视觉历史，同一个世界被重复编码无数次；
- **视角不一致**：同一实体在不同视角的预测中可能出现在不同位置或表现出不同状态；
- **扩展性差**：模拟世界的成本与同时观看的视角数线性绑定，无法支持大量玩家共享同一个世界。

论文提出 **MASS（Multiplayer world models with Authoritative Shared State）**，借鉴传统多人游戏“权威服务器 + 客户端渲染”的架构，将世界动态预测与视角渲染彻底解耦。其核心思想是：由一个**逻辑引擎**只推进一份全局、权威的**类型化状态**（typed state），再由一个**渲染引擎**基于该状态按需为任意相机生成视图。这样世界只需模拟一次，渲染成本与视角数无关，且所有视角天然共享同一个状态，从构造上保证一致性。

## 2. 论文提出的方法论

### 2.1 核心思想

将世界模型拆分为两大组件：
- **逻辑引擎（Logic Engine）**：负责从当前世界状态 + 联合玩家动作 + 外生输入，预测下一时刻的完整类型化状态；
- **渲染引擎（Rendering Engine）**：从预测出的类型化状态和相机参数，生成对应的 RGB 图像。

预测出的类型化状态同时充当：
- 唯一的循环记忆（recurrent memory）；
- 客户端同步的权威共享对象（synchronization reference）；
- 所有视角渲染的唯一数据源。

### 2.2 关键技术细节

#### 世界状态 Tokenizer（World State Tokenizer）
- 每个游戏由一个声明式**schema**定义，描述实体种类、字段及其取值范围、实体数量：
  \[
  \Sigma_g = \{ (\text{kind}_j, \text{fields}_j, \text{count}_j) \}_{j=1}^{J_g}
  \]
- 每个实体被序列化为一条定长的 token 序列，包含：
  - 实体当前字段值；
  - 局部邻域上下文（如网格周围信息）；
  - 关联玩家动作（若有）；
  - 该实体对应的外生随机性份额。
- 编码采用类型标签固定位置布局，能无损地从 token 序列还原完整状态。

#### 逻辑引擎
- 使用 decoder-only Transformer（宽 256、6 层、8 头、约 5.66M 参数）。
- 逐记录地自回归预测下一时刻的 token，条件依赖自身前缀和当前状态中计算的邻域上下文。
- 每个记录的 self-attention 仅在该记录内部进行，记录之间无注意力交互，从而支持 1024 实体的大规模并行批处理。
- 通过 schema 派生掩码保证输出字段类型合法，并利用确定性规则强制跨记录约束（如排序、去重）。
- 每个 tick 只运行一次世界级转移，预测状态直接作为下一时刻的输入。

#### 渲染引擎
- 将完整状态经相机投影转换为 16 通道的相机局部张量（包含占用、语义角色、所有者、深度等）；
- 用残差 U-Net 将该张量转换为 RGB 帧；
- 所有相机从同一份状态解码，因此从构造上保证跨视角一致，且渲染不影响世界推进。

#### 客户端逻辑（Client-side Prediction）
- 客户端缓存最新权威状态；当服务器更新暂时缺失时，用同一逻辑引擎在本地推进该状态；
- 只使用本玩家自己的动作、其他玩家视为 no-op，直到收到新的服务器状态后再重新对齐。

## 3. 实验设计

### 3.1 Benchmark 场景

- **匹配的多智能体 Snake 基准（matched multiplayer Snake benchmark）**：48×48 场地，最多 8 个玩家，固定测试集、相机轨迹、联合动作，128×128 分辨率、128 tick 的 rollout。
- **跨游戏验证**：Snake、Crate Pusher、Pac-Man、Tank Battle、Lunar Touchdown、Frogger、Tron、Bomberman 共 8 个游戏，用于评估渲染质量和架构通用性。
- **大规模场景**：1,024 个玩家实体的 Snake、Crate Pusher 和 Pac-Man 世界，验证扩展性和长程稳定性。

### 3.2 对比方法

- **MultiWorld**：公开的耦合多视角视频世界模型，官方代码在匹配数据集上重训；
- **B-PV**：每视角独立的视频预测器（per-view video predictor）；
- **B-SL**：共享视觉潜变量的预测器（shared visual latent predictor）；
- **B-UN**：密集联合状态预测器（dense joint-state predictor），保留 MASS 的渲染管道但把类型化载体替换为稠密状态网格。

### 3.3 评估指标

- 图像质量：LPIPS；
- 状态恢复：冻结 parser 的全体语义、实体计数、位置、事件 F1；
- 跨视角一致性：X-view disagreement；
- 结构有效性：Invalid 比例；
- 直接状态评估：字段准确率、完整状态精确匹配、矛盾/失效状态比例；
- 另设计了 SRSC（State-Referenced Semantic Correctness）协议，用 VLM（Qwen3.5-27B）对逻辑、渲染、端到端进行语义分离评估。

## 6. 论文的主要结论与发现

- MASS 在匹配 Snake 上显著领先：LPIPS 0.098（次优 B-UN 为 0.123，MultiWorld 为 0.277）；状态恢复 0.764，是最强视频基线 B-PV（0.128）的 6 倍；跨视角不一致为 0.000，而其他基线最高达 1.000。
- 类型化状态是保持实体身份和位置的关键：B-UN 能维持较好的 LPIPS（0.123），但其 Parser 恢复为 0，说明像素级相似不代表世界状态可恢复。
- MASS 能支持 1,024 个玩家实体递归 10,000 步，且逻辑引擎的单次世界转移成本与视角数无关。
- 同一架构经 schema 配置可直接迁移到多个游戏（8 个游戏均获得合理重建质量，PSNR 23.72–40.24 dB）。
- 客户端本地预测在缺少服务器更新时，本地玩家位置零偏移，远程对象因未知动作而随时间漂移，但可通过新版本状态直接校准。
- 状态的可直接评估性使误差定位成为可能：渲染器在给定正确状态时不会随时间累积语义漂移，而端到端性能衰减主要源于逻辑引擎。

## 7. 优点

- **架构创新性强**：首次将“权威共享状态”引入学习型世界模型，将多人游戏中的服务器-客户端契约移植到生成式模拟中，概念清晰且实用。
- **状态与渲染解耦带来多方面的可直接收益**：跨视角一致性由构造保证，无需额外的协调机制；计算成本与视角数无关；状态本身可被程序化评估，不像像素潜变量那样黑箱。
- **实验设计严谨**：设置了多个受控基线（B-PV/B-SL/B-UN），尤其是 B-UN 直接对比“稠密状态 vs. 类型化状态”；统一训练数据与预算，降低公平性争议。
- **多维度评估体系**：常规图像质量指标之外，还设计了状态恢复、事件 F1、结构有效性、直接状态精度、SRSC 语义分解等，能够细致区分逻辑与渲染的错误来源，增强结论可信度。
- **跨游戏扩展验证**：证明同一架构可以仅通过声明式 schema 适配不同游戏，说明方法具有一定通用性。
- **长程稳定性验证充分**：给出 4096 步无崩溃、无结构矛盾的实测结果，并统计了状态多样性与吸引子行为，具有较强的说服力。

## 8. 不足与局限

- **实验场景相对简单**：所有游戏均为 2D/2.5D 网格类游戏（Snake、Pac-Man、Tron 等），未验证复杂的 3D 环境和物理丰富的多智能体交互。
- **详细对比多集中在 Snake**：跨游戏部分只报告了渲染质量指标，缺乏各游戏上的端到端多人预测准确性和与其他方法的对照。
- **训练算力信息披露不完整**：未给出完整 GPU 数量、总训练时长、推理吞吐等具体数字，复现门槛较高。
- **可扩展性测试仍有边界**：1,024 实体是基于“单次状态转移”和“渲染负载分离”验证的，实际端到端大规模多人并发系统的网络传输、同步策略等系统工程问题未充分分析。
- **类型化状态严重依赖 schema 定义**：schema 本身需要人为设计，状态空间覆盖受到声明约束限制，对于开放式环境或连续状态空间（如真 3D 物理）的适应能力尚不明确。
- **客户端预测仅假设其他玩家 no-op**：对实际复杂多玩家行为的预测误差估计可能过于乐观，实验仅测试到 8 tick 的缺失窗口。
