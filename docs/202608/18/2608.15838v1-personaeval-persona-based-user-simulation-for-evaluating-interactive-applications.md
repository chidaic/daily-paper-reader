## 摘要
真实用户研究对于理解人们如何与测试中或已部署的系统交互至关重要。然而，在实践中，这些研究往往成本高昂、耗时且难以扩展。为了应对这些挑战，我们引入了PersonaEval，一个基于人物角色的用户模拟框架，可在多种交互环境中近似真实用户行为。PersonaEval将来自现有角色数据集的模拟用户连接到特定任务的应用界面，并收集交互轨迹和结果。PersonaEval提供了一种即插即用的评估工作流程，其中被评估的应用可以轻松更换。在此演示中，我们展示了PersonaEval在三种交互式应用形式上的应用：调查问卷、聊天机器人和Web应用。这些示例共同表明，PersonaEval可以支持跨不同交互环境的可重复、可并行和可扩展的评估，同时产生面向用户的反馈和特定任务的行为。

## Abstract
Real user studies are important for understanding how people interact with systems under test or already deployed. In practice, however, they are often costly, time-consuming, and difficult to scale. To address these challenges, we introduce PersonaEval, a persona-based user simulation framework that approximates real-user behavior across diverse interactive settings. PersonaEval connects simulated users drawn from existing persona datasets to task-specific application interfaces and collects the interaction trajectories and outcomes. PersonaEval provides a plug-and-play evaluation workflow in which the application being evaluated can be easily changed. In this demo, we present PersonaEval on three forms of interactive applications: surveys, chatbots, and web applications. Together, these examples show that PersonaEval can support repeatable, parallelizable, and scalable evaluation across different interaction settings, while producing user-oriented feedback and task-specific behavior.

# 2. 方法论

## 核心思想
- 将现有人物角色数据集中的用户画像与任务特定应用接口对接，通过 LLM 扮演“真实用户”与应用交互，并收集统一格式的交互轨迹和结果。
- 设计为**模块化即插即用**系统：同一批人物角色可复用于不同应用，被测应用可通过适配器轻松更换。

## 系统架构
- **Persona API**：将人物角色模型包装为模拟用户。系统提示包含应用描述、人物角色档案和目标上下文模板，指导用户：
  - 基于人物角色推断现实目标及约束/偏好；
  - 逐步揭示需求（而非一次全部说出）；
  - 对应用响应做出确认、反驳或澄清请求；
  - 保持消息简短（1–3 句）。
- **Task API**：封装被测应用所需环境（如聊天接口、浏览器环境），定义任务指令、交互协议和评价表格。
- **任务适配器**：
  - **Survey**：模拟用户阅读产品简报/背景后完成结构化问卷，输出答案、理由、置信度与轨迹。
  - **Chatbot**：多轮对话完成目标，结束后模拟用户自填评估表（目标满足、约束遵循、偏好匹配、澄清质量、总体评分）。
  - **Web**：模拟用户在浏览器中完成封闭式任务（搜索、比较、加入购物车、沙箱结算、到达确认页），并评估易用性、信息质量、需求满足度等。

## 关键技术细节
- 人物角色来源：从现有数据集（NVIDIA Nemotron-Personas-USA、PersonaHub、PRIMEX、OASIS）中选取 336 个精选档案，主实验使用 Nemotron 子集。
- 人物角色选择：将应用描述与人物角色档案做嵌入相似度排序，每个应用取最相关的 50 个 personas。

# 6. 主要结论与发现

- PersonaEval 能支持跨问卷、聊天机器人、Web 环境的可重复、可并行、可扩展评估，并生成用户导向反馈。
- **应用间差异**：聊天机器人任务满意度适中且分散（受人物角色目标/知识影响大）；问卷和 Web 任务评分更集中，结果更稳定。
- **人物组间差异**：美容、医疗、电影等任务中不同人物组评分差异较大。例如美容场景中，沙龙配方用户和美甲专业人士评分较低（因为需求更专业、目录匹配差），日常护理用户评分较高（匹配度好）。
- **人物对齐性**：模拟交互与分配的人物角色总体一致性高（人工 1–5 分）；但在需要多轮表达专业知识、个人约束或领域关注时，分数略有下降。
- 具体轨迹显示，人物角色能够影响目标设定、交互风格、批评角度和最终评价（如会计背景用户期望具体税后计算，医疗技术人员期望更针对工作场景的随访建议）。

# 7. 优点

- **模块化即插即用**：Persona API 与 Task API 分离，便于将同一批人物角色用于不同应用，降低重复构建成本。
- **统一评估工作流**：不同应用类型共享同一套模拟用户和结果收集格式，便于跨应用比较。
- **利用现有人物角色数据集**：避免人工编写角色，同时保证人物角色的多样性和复用性。
- **人物角色驱动的模拟方式**：强调逐步揭示需求、保持角色一致，比单轮静态测试更接近真实交互。
- **多应用验证**：覆盖问卷、聊天机器人、Web 三类典型界面，展示了广泛适用性。
- **多维度评估**：不仅记录任务结果，还收集用户自述评分、人物对齐、任务接地性等，信息丰富。
- **低成本、可并行、可重复**：适合早期开发迭代和横向对比。

# 8. 不足与局限

- **应用覆盖有限**：只包含调查、聊天机器人和 Web 场景，未覆盖移动应用、语音交互、游戏、AR/VR 等更多交互形式。
- **缺少真实用户对照**：没有验证模拟结果与真实用户研究的一致性，模拟偏差（如效果量扩大、敏感话题保真度降低）未被校正。
- **缺少基线与消融实验**：未与 PersonaGym、SimBench 等既有模拟评估基准或真实用户研究对比，组件贡献未做消融分析。
- **人物角色选择可能引入偏差**：仅通过嵌入相似度筛选人物角色，可能无法充分代表目标用户群，且聚类分组轮廓系数低。
- **人工评估的可靠性有限**：人物对齐分数依赖人工裁判，但没有报告评分者信度，也未做大规模验证。
- **生成模型固有偏差**：LLM 模拟用户可能表现出回复长度偏长、偏好流行性偏置等已知失败模式，论文未系统分析。
- **评估形式在某些任务中共享**：金融和医疗任务复用通用聊天机器人评估表，缺少领域特定评估维度，可能不够精细。
